0. Raw Ingredients (from scrape)

These are the base quantities extracted from FirstCycling pages. Everything downstream is computed from them. Each is pickled as part of a Race or Stage object, then migrated into SQLite during Stage 02 of the pipeline.

place

raw int | "DNF" | "DNS" | "OTL" | …

Finishing position as displayed on FirstCycling, or a non-numeric status string for non-finishers.

source: Race.populate_race() (scrape)

time_gap

raw float seconds ≥ 0, winner = 0

Seconds behind the stage/race winner, parsed from FirstCycling's gap column. Missing for DNFs.

bib (→ team_bib, personal_bib)

raw int, e.g. 137 → team 13, personal 7

Race number split into team number (all but last digit) and personal number (last digit) via migrate_bib_number_columns(). Used for team-role features (personal_bib == 1 means team leader).

Gradient feature inputs

raw 4 floats + winning_time

Used only by race-profile scoring (Section 6). Extracted by the gradients pipeline step from elevation data and finishing-time distributions.

2. Rider Running State (rider_competition_snapshots)

All rider history features are computed by walking competitions chronologically and maintaining running sums/counts per rider in a RiderRunningState. At each race start, the current state is frozen as a snapshot — so the rider's features as of 2020-07-01 only use races dated strictly before 2020-07-01. This is the key anti-leakage guarantee of the entire system.

Universal defaults: safe_avg(s, c) = round(s/c, 2) if c > 0 else 4.0 — a rider with no history in a given category gets a neutral 4.0 (mid-field). Bucket 7 (DNF) results are skipped entirely by RiderRunningState.update() and do not increment any sum or count.

stage_avg_bucket, stage_count (and one_day, gc)

rider avg ∈ [0, 6]; count ∈ ℕ

Incremental mean and count of finishing buckets across prior competitions of each type.

# RiderRunningState.update(bucket, comp_type, …) if bucket == 7: return # DNFs skipped if comp_type == 'stage': stage_bucket_sum += bucket stage_count += 1 # Snapshot stage_avg_bucket = stage_bucket_sum / stage_count # or 4.0 if count=0

same formula for: one_day_avg_bucket / one_day_count, gc_avg_bucket / gc_count

src: engineering_tools/feature_precomputation.py → RiderRunningState.update() / get_snapshot()

wt_avg_bucket, pro_avg_bucket, d1_avg_bucket

rider avg ∈ [0, 6]; count ∈ ℕ

Same incremental mean/count pattern, bucketed instead by tour category (World Tour, Pro, Division 1). Tells the model "how does this rider fare at each level of competition".

if race_category == 'wt': wt_bucket_sum += bucket wt_count += 1 # …same for 'pro', 'd1' wt_avg_bucket = wt_bucket_sum / wt_count # or 4.0

sprint_avg_bucket, mountain_avg_bucket, … (profile-weighted)

rider ∈ [0, 6], weighted

The six profile averages use continuous weighting by race profile scores: instead of assigning each race to a single profile bucket, each race contributes to every profile average proportionally to how "sprinty" / "mountainy" / etc. it was. A rider's sprint bucket ends up reflecting both their performance and how sprinter-friendly their races actually were.

# For every prior race (with its race_profile scores): sprint_weighted_sum += bucket * race_profile.sprint sprint_weight_sum += race_profile.sprint # …repeat for mountain, hilly, rolling, breakaway, time_trial # Snapshot def safe_weighted_avg(ws, w): return round(ws / w, 2) if w > 0.1 else 4.0 sprint_avg_bucket = safe_weighted_avg(sprint_weighted_sum, sprint_weight_sum)

note: race_profile.sprint + mountain + … = 1.0 (non-TT), so each race contributes a total weight of 1 across all six averages combined.

floor: weight_sum must exceed 0.1 to produce a real average — otherwise defaults to 4.0.

best_profile

rider ∈ {sprint, mountain, hilly, rolling, breakaway, time_trial, unknown}

The profile where the rider's weighted-average bucket is lowest (= best performance). Falls back to "unknown" if every weight sum is ≤ 0.1 (the rider has no meaningful profile data yet).

profile_avgs = { 'sprint': safe_weighted_avg(sprint_ws, sprint_w), 'mountain': safe_weighted_avg(mountain_ws,mountain_w), # … etc } best_profile = min(profile_avgs, key=profile_avgs.get) # argmin if any(w > 0.1 for w in weight_sums) else 'unknown'

races_career, races_this_year

rider int ≥ 0

Total competitions the rider has entered prior to the current race (both exclude DNFs). races_this_year resets each calendar year.

total_races += 1 # on every update() races_by_year[race_year] = races_by_year.get(race_year, 0) + 1 # Snapshot races_career = total_races races_this_year = races_by_year.get(race_year, 0)
Only riders with races_career ≥ 10 enter the training set (DataConfig.min_races_career) — keeps training signal tied to rest-of-career rather than noisy newcomers.

3. Form & Recency

Form features use a separate, time-windowed buffer (RiderFormHistory, up to 50 most-recent entries) — not the cumulative running state. A qualifying race must be strictly before the target date, within the last 90 days, and within the same calendar year. For GC targets, stages from the same race are excluded to avoid trivial self-reference.

Qualifying window

form
effective_date = race_start_date if comp_type == 'gc' else target_date min_dt = max(effective_date − 90 days, datetime(target_year, 1, 1)) qualifying = [e for e in history if min_dt ≤ e.date < effective_date and not (comp_type == 'gc' and e.race_id == target_race_id and e.race_year == target_year)] recent_5 = qualifying[-5:] # last up to 5 qualifying entries

form_recent_avg_bucket

form ∈ [0, 6], default 4.0
form_recent_avg_bucket = sum(e.bucket for e in recent_5) / len(recent_5)

form_recent_best_bucket, form_recent_count

form
form_recent_best_bucket = min(e.bucket for e in recent_5) # best result form_recent_count = len(recent_5) # 0 to 5

form_delta

form typically [−3, +3]; negative = improving

Difference between recent form and the rider's career average. Negative = rider is currently doing better than their long-term baseline.

form_delta = form_recent_avg_bucket − career_avg_bucket # where career_avg_bucket is passed in from the running-state snapshot

derived flag: is_improving_form = (form_delta < −0.5)

form_profile_recent_avg

form ∈ [0, 6], default 4.0

Mean bucket of the subset of recent races whose dominant profile matches the upcoming race's dominant profile. Answers "how has this rider been doing in this kind of race lately?".

profile_buckets = [e.bucket for e in recent_5 if e.profile == target_profile] form_profile_recent_avg = mean(profile_buckets) if profile_buckets else 4.0

days_since_last_race

form int ∈ [0, 365], capped
days_since = (effective_date − recent_5[-1].date).days days_since_last_race = min(days_since, 365) # cap at 365 # default when no recent race: 90

derived flags: is_fresh = (days < 14), is_rusty = (days > 45)

3b. Trajectory & EMA Form (v2/v3) live · 2026-06-10

Fifteen snapshot columns that measure where a rider's level is heading, not just where it has averaged. Built on the within-race finishing percentile (100 = winner, 0 = last finisher) rather than buckets, exponentially decayed so last month outweighs three months ago. Shipped 2026-06-10 after a 5-fold gate (winner capture +0.64pp; late-career calibration for 37+ riders fixed from 1.327 to 1.061). These columns are NULL by design when a rider lacks qualifying history — LightGBM consumes NaN natively, and they are deliberately exempt from imputation. They are also re-aged to prediction day at inference (see live form re-aging).

Qualifying entries & the percentile

form v2/v3
pct(entry) = within-race finishing percentile, 100 = winner, 0 = last # only percentile-bearing results count (rows with a NULL percentile are skipped) candidates = races strictly before the effective date (GC: effective date = race start; same-(race_id, year) rows excluded) win365 = candidates within the last 365 days

v2_ema_pct_h30, v2_ema_pct_h60, v2_ema_pct_qw_h60, v2_ema_eff_n_h60, v2_ema_bucket_h60

form v2 pct ∈ [0, 100]; eff_n ≥ 0

Exponential moving averages over the 365-day window. The half-life sets the memory: h30 reacts within a month, h60 is steadier. The quality-weighted variant counts World Tour results more than .1 results.

w_i = exp(−ln2 · Δdays_i / halflife) # halflife ∈ {30, 60} days v2_ema_pct_h30 / _h60 = Σ w_i·pct_i / Σ w_i v2_ema_pct_qw_h60 = Σ (w_i·c_i)·pct_i / Σ (w_i·c_i) # c: wt=1.0, pro=0.65, d1=0.4 v2_ema_eff_n_h60 = Σ w_i # effective sample size v2_ema_bucket_h60 = Σ w_i·bucket_i / Σ w_i # empty window → all NULL (eff_n = 0)

src: engineering_tools/form_team_features.py → get_trajectory_form_features()

v3_season_pct_cur / _prev / _prev2, v3_season_delta, v3_season_delta_prev

form v3

Season-over-season trajectory. Prior seasons come from never-pruned per-season aggregates, so a long buffer isn't needed; a season only counts with ≥ 3 percentile-bearing races.

v3_season_pct_cur = mean pct, current calendar year (exclusion rules applied) v3_season_pct_prev = season aggregate, year − 1 # NULL if < 3 races v3_season_pct_prev2 = season aggregate, year − 2 # NULL if < 3 races v3_season_delta = cur − prev # NULL if either side NULL v3_season_delta_prev = prev − prev2 # NULL if either side NULL

v3_slope365, v3_races365, v3_peak_season_pct, v3_decline_from_peak, v3_season_races_cur

form v3

The within-year trend line and the career-arc reference point. v3_decline_from_peak is the veteran-bias killer: a rider 20 points below their best season stops being priced on the glory years.

v3_slope365 = linreg slope of pct vs days over win365, scaled to pct-points per 30 days # NULL if < 5 races v3_races365 = |win365| v3_peak_season_pct = best completed-season mean pct with ≥ 10 races (seasons before the current year) # NULL if none v3_decline_from_peak = v3_season_pct_cur − v3_peak_season_pct # NULL if either NULL v3_season_races_cur = race count, current season
Do not add imputation defaults for any v2_*/v3_* column. Their names deliberately avoid the pattern-based imputation in feature_engineering.py ('avg_bucket', '_count'); NULL routes down LightGBM's trained "no history" branch.

Live form re-aging (inference only)

serving

Snapshots freeze form as of each rider's last race, which goes stale between races (stored days_since_last_race averaged 7 days where the truth at prediction time was 43). 4. Team Context

Team features use a two-pass algorithm per competition: first collect every rider's snapshot into a team-indexed dict, then compute stats over each rider's teammates (self is excluded). "Quality" is defined concretely as each teammate's weighted career average bucket.

Teammate career average (per-rider input)

team ∈ [0, 6], default 4.0
stage_sum = stage_avg_bucket * stage_count one_day_sum = one_day_avg_bucket * one_day_count gc_sum = gc_avg_bucket * gc_count total_count = stage_count + one_day_count + gc_count career_avg = (stage_sum + one_day_sum + gc_sum) / total_count if total_count > 0 else 4.0

src: TeamFeatureComputer._compute_career_avg()

team_quality_mean/median/std/min/max/p25/p75

team 7 floats, ∈ [0, 6]

Distribution statistics over the career averages of the rider's teammates at this race. Percentiles use linear interpolation over the sorted list.

teammate_avgs = [_compute_career_avg(snap) for teammate in team] team_quality_mean = mean(teammate_avgs) team_quality_median = percentile(sorted(teammate_avgs), 50) team_quality_std = stdev(teammate_avgs, team_quality_mean) team_quality_min = min(teammate_avgs) team_quality_max = max(teammate_avgs) team_quality_p25 = percentile(sorted(teammate_avgs), 25) team_quality_p75 = percentile(sorted(teammate_avgs), 75)

team_size, team_depth

team int ≥ 0
team_size = len(teammate_avgs) # excludes self team_depth = sum(1 for v in teammate_avgs if v < 4.0) # "above-average" count

defaults (lone rider): all quality stats = 4.0, std = 0.0, size = 0, depth = 0

One row per competition. Computed from the set of rider snapshots at the start line — so these describe how strong and experienced the rest of the field is, before the race is run.

experience_* (7 stats on races_career)

bucket_* (7 stats on overall rider quality)

Built from a per-rider "overall bucket" that combines every type-specific sum and count — a weighted career average, identical in spirit to what TeamFeatureComputer uses.

5b. Within-Race State (rider_race_state) live · 2026-06-09

23 features describing a rider's situation inside an ongoing stage race, written by pipeline step race-state for stage k ≥ 2 of every multi-stage race (and the GC competition, with state after the final stage). GC standings are reconstructed as cumulative stage time — validated against stored final GCs (median top-10 error ~10 s); races disagreeing by > 120 s get no state rows. Attached to training/serving frames by LEFT JOIN; missing rows (stage 1, one-days, coverage gaps) impute neutral defaults plus race_state_missing=1. 6. Race Profile Scores

The 6 race profile scores drive both training-time weighting of sprint_avg_bucket/etc. and inference-time interaction features. They're derived from four slope/distribution statistics of the race's finishing-time profile, combined via sigmoids and Gaussians, then normalized to sum to 1. Short (< 70 min) races are hard-classified as time trials.

Basis functions

race
sigmoid(x, center, steep) = 1 / (1 + exp(−steep * (x − center))) gaussian(x, center, width) = exp(−width * (x − center)**2) log_var_slope = log10(variance_slope)

TT short-circuit

race
if winning_time < 4200: # < 70 minutes return RaceProfileScores( sprint=0, mountain=0, hilly=0, rolling=0, breakaway=0, time_trial=1.0)

note: time_trial is always 0 for non-TT races; the other five sum to 1.

sprint_raw

race

High field coherence (half the field together) + low variance slope → classic bunch sprint.

sprint_raw = sigmoid(breakdown, center=50, steep=0.1) * sigmoid(−log_var_slope, center=6, steep=2.0)

mountain_raw

race

No breakdown of field structure (gradual selection) + high variance slope → big GC days / mountain stages.

breakdown_penalty = 1.0 if breakdown == 0 else exp(−0.05 * breakdown) mountain_raw = breakdown_penalty * sigmoid(log_var_slope, center=−5, steep=2.0)

hilly_raw

race

Moderate breakdown (~35%) and field clumping → puncheur-style finish.

hilly_raw = gaussian(breakdown, center=35, width=0.005) * sigmoid(clumpiness_slope, center=0.004, steep=400)

rolling_raw

race

Moderate variance slope without field fracture → rolling terrain.

breakdown_penalty = 1.0 if breakdown == 0 else exp(−0.1 * breakdown) rolling_raw = breakdown_penalty * gaussian(log_var_slope, center=−5.5, width=0.5)

breakaway_raw

race

Early selection (~18% breakdown) plus a shrinking lead group (negative biggest-group slope) → successful breakaway.

breakaway_raw = gaussian(breakdown, center=18, width=0.01) * sigmoid(−biggest_group_slope, center=0.005, steep=500)

Normalization

race each score ∈ [0, 1], sum = 1
total = sprint_raw + mountain_raw + hilly_raw + rolling_raw + breakaway_raw + 1e-10 race_sprint_score = round(sprint_raw / total, 4) race_mountain_score = round(mountain_raw / total, 4) race_hilly_score = round(hilly_raw / total, 4) race_rolling_score = round(rolling_raw / total, 4) race_breakaway_score = round(breakaway_raw / total, 4) race_time_trial_score = 0.0 # non-TT races race_dominant_profile = argmax(all six scores)

7b. Contested-Comparison Elo Rating live

A chess-style rating built from the only finishing orders that are informative: riders who genuinely contested against each other. Deep-bunch order (positions 11+ of a group) generates no comparisons. Replayed chronologically over every result sheet since the data starts, snapshotting each rider's rating as of each competition (~575K snapshot rows) — zero look-ahead. First feature family since trajectory form to clear the winner-capture gate: +1.25pp ± 0.65, positive in all 5 CV folds, alongside market_avg_log_loss −0.0019 ± 0.0017 (4/5). Sanity checks: 2025's top-15 is Pogačar #1 then the world-class sprinters (high comparison volume); a hot neo-pro shows up at a high rating with low n long before his career averages catch up.

Which comparisons count

elo
# groups = same-time clusters (1.0 s consecutive-gap rule) 1. sprint order inside the winner's group: ordered pairs among its first 10 positions # they raced for it 2. adjacent group-vs-group: each of the first 10 of group g beats each of the first 10 of group g+1 3. deep-blob internal order (positions 11+): no comparisons # noise, ignored

src: prediction_tools/contested_rating.py

Rating update (per competition, batch)

elo init 1500, K = 4, scale 400
expected(a beats b) = 1 / (1 + 10^((R_b − R_a) / 400)) # all expectations use PRE-competition ratings; gains applied as one batch ΔR_a = Σ_pairs K · (S − expected) # S = 1 win, 0 loss; K = 4.0 # competitions processed in (date, competition_id) order; # K=4 chosen by sweep on 2016+ rated-pair accuracy (0.5521 @ K=4)

contested_rating, contested_rating_n, contested_rating_delta90, contested_rating_vs_field

elo
contested_rating = rating strictly before this competition contested_rating_n = cumulative comparisons before it # confidence proxy contested_rating_delta90 = rating now − rating 90 days ago # vs 1500 if first rated < 90 d ago contested_rating_vs_field = rating − mean rating of this startlist # all NaN for riders never seen in a contested comparison (never zero-filled) # training: merge_asof backward, allow_exact_matches=False (as-of-then) # serving: rating as of today from the production snapshots artifact

Temperature calibration

model

Post-hoc calibration fit on the early-stop set. When T ≠ 1, probabilities are re-softmaxed from raw logits divided by temperature. T > 1 flattens; T < 1 sharpens.

if temperature ≠ 1.0: raw_scores = model.predict(X, raw_score=True) # logits scaled = raw_scores / temperature # numerically-stable softmax exp_scaled = np.exp(scaled − scaled.max(axis=1, keepdims=True)) proba = exp_scaled / exp_scaled.sum(axis=1, keepdims=True) else: proba = model.predict(X) # native LGBM softmax

9. Evaluation Metrics — the experiment gate

How candidate upgrades are judged (5-fold full-year CV at the production start date). Since 2026-06-11 the primary gate is market probability quality; winner capture stays as a reported diagnostic. Rationale: the betting use case pays on calibrated prices, and several shelved experiments had improved probability quality but were rejected on top-1 — the gate now measures what matters.

MarketProbabilityEvaluator

eval headline: market_avg_log_loss (lower = better)

Scores every priced rider against four binary cumulative markets. This fixes the old top4_log_loss, which conditioned on the outcome (scored only riders who finished top-15) and therefore under-penalized overconfident prices on riders who flopped.

for market m in {win, podium, top5, top15}: # buckets [0], [0,1], [0..2], [0..3] y_i = 1 if rider i's outcome ∈ m else 0 # EVERY rider, no conditioning p_i = predicted cumulative probability for m m_log_loss = −mean(y·log p + (1−y)·log(1−p)) m_brier = mean((p − y)²) m_cal_ratio = Σp / Σy # >1 overconfident, <1 shy market_avg_log_loss = mean(win_ll, podium_ll, top5_ll, top15_ll) # ★ the gate

src: prediction_tools/evaluation.py → MarketProbabilityEvaluator

The honest-pool frame

eval

Evaluation pools now include non-finishers (the real startlist), not just riders who completed the race. A model that prices a serial abandoner like a sure finisher gets punished. This frame is what made the DNF multiplication's value visible — under the legacy finishers-only frame it looked harmful.
